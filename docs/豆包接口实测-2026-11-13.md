# 豆包工作接口逆向 · 实测交接（2026-11-13）

> 结论来源：真实浏览器抓包 + 裸 Cookie 重放验证，非推测。
> 报文体模板见 `doubao.js` 的 `_buildBody()`，此处只记结论。

## 一、对话接口（已完整验证）

`POST https://www.doubao.com/chat/completion`，`Accept: text/event-stream`，Cookie 是唯一鉴权。

- **不需要签名**：URL 里的 `msToken`/`a_bogus` 可以完全不带，服务端不校验（裸调 200 正常出流）
- **设备参数必须带**：`device_id` / `web_id` / `tea_uuid` / `fp` 缺失时返回 200 但不触发推理，只有心跳+ACK+用户回显，静默挂起（最大的坑）
- 可直接复用的硬编码值：`device_id=7707509248230065699`、`web_id=7707509253662393906`、`tea_uuid=7707509253662393906`、`fp=verify_mwehdj77_p7te0LWd_xEFZ_4N2S_8jDq_L7Zl4uO5iI5F`；`web_tab_id` 每次随机 UUID
- Cookie 失效表现：HTTP 401，或 200 但 content-type 变 HTML（跳登录页）

## 二、模型切换（model_item_key）

工作模式：`mode_id="3"`、`agent_mode=1`、`reasoning_effort=3`。`model_item_key` 在 `conversation_init_ext` 和 `model_config` 两处都要填。

| 菜单 | 倍率 | model_item_key |
|---|---|---|
| 自动 | 小额免费 | 未抓（默认不传或 "0"） |
| 豆包 2.1 Lite | 0.01x | `seed-lite-7b` ✅ |
| 豆包 2.1 Pro | 0.65x | 未抓 |
| DeepSeek V4.1 Flash | 0.01x | `person-deepseek-v4-1-flash-261017` ✅ |
| Kimi K3.1 Pro | 0.95x | 未抓 |
| Kimi K3.1 Pro 高速 | 1.44x | 未抓 |
| Kimi K3 | 1.48x | 未抓 |
| GLM 5.3 | 0.80x | 未抓 |
| GLM 5.3 Flash | 0.08x | 未抓 |
| DeepSeek V4 Pro | 0.46x | 未抓 |

普通对话模式：`mode_id="1"`、`agent_mode=2`、`model_item_key="0"`。

**抓新 key 的方法**：网页版 → 欢迎页选「工作」→ 输入框左下角「低」按钮（`data-testid=chat_input_action_model`）→ 选模型 → 发一条消息 → F12 Network 找 `chat/completion` → request body 里的 `model_item_key`。

**验证是否真生效**：别信模型自认知（壳层统一答"豆包"）。看 SSE_ACK 的 `ack_client_meta.conversation_info.extra` 里服务端回写的 `model_item_key`，回写值等于传入值才算生效。

## 三、SSE 事件

| 事件 | 处理 |
|---|---|
| SSE_HEARTBEAT | 忽略 |
| SSE_ACK | 会话创建确认，含 conversation_id；extra 回写 model_item_key（验证用） |
| FULL_MSG_NOTIFY | 用户消息回显，忽略（别当 AI 回复） |
| STREAM_MSG_NOTIFY | AI 首块：`content.content_block[].content.text_block.text` |
| STREAM_CHUNK | 增量：`patch_op[]` 中 `patch_object==1` 的 `patch_value.content_block[].content.text_block.text`；`patch_object==111` 是 tts_content，忽略 |
| CHUNK_DELTA | 纯文本增量 `{"text":"..."}`，最干净，优先用 |
| SSE_REPLY_END | 流结束 |
| STREAM_TIMEOUT_CONTROL | 忽略 |

计费信息在 STREAM_MSG_NOTIFY 的 `ext.commerce_usage_data_v1`（0.01x 模型实测显示"免费"档）。

## 四、额度/账号接口（已验证）

均为 POST + JSON + Cookie，不需要签名参数（比对话接口更松）。

| 接口 | 用途 | 状态 |
|---|---|---|
| `/alice/profile/self?aid=497858&version_code=20800` | Cookie 健康检查（code:0 + 用户信息即有效） | ✅ |
| `/alice/commerce/sale/subscription/quota/summary/` | 订阅额度总览（"免费体验"档/订阅状态） | ✅ |
| `/alice/commerce/marketing/card/balance/` | 额度卡片余额 | 见过未细验 |
| `/alice/commerce/sale/subscription/entry/config/` | 订阅入口配置 | 见过未细验 |

## 五、签到接口 —— 未抓到

**没有抓到签到接口。** 网上流传的 `work.doubao.com/api/sign/daily` 是 AI 编造的，不存在。

已知额度规则（用户口述，未接口验证）：签到 200/天、周一翻倍 400、30 天有效；当日登录免费额度当天清零；临时限流多数第二天恢复；同 IP 多账号高并发会永久封号。

补抓方法：登录网页版 → 工作模式找签到入口（可能在额度/会员页或侧栏）→ 点签到 → F12 抓 POST（大概率在 `/alice/commerce/` 或 `/biz/activity/` 下）→ 确认方法/body/幂等性（重复调用是否报错）。

## 六、登录相关发现（备用）

- 网页版手机号登录区号仅 +86/+852/+853/+886，无 +1
- 登录弹窗有隐藏二维码入口：`[data-testid="qrcode_switcher"]` 切换，`[data-testid="qrcode_image"]` 显示；豆包/飞书 App 可扫，实测偶发"登录失败请重新扫码"
- 手机号+验证码流程可用，验证码输入框是特殊组件，需逐字输入
- 飞书 OAuth：`accounts.feishu.cn`，`client_id=cli_a92bdaf158381bdf`，redirect 回 `www.doubao.com/auth/callback`；飞书国内版仅 +86
