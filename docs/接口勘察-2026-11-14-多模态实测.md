## 一、客户端身份（重要）

`SSE_ERROR 710022004`（要求人机验证）。客户端身份完全不受影响：

| `aid` / `real_aid` | `582478` |
| `channel` | `win` |
| `client_platform` | `pc_client` |
| `doubao_device_platform` / `web_platform` | `desktop` |
| `pc_version` / `doubao_pc_version` | `2.35.12` |

| `fp` | `verify_2955100808290061` |

| UA | `…Chrome/147.0.7727.149 Safari/537.36 SamanthaDoubao/2.35.12` |
| Referer | `chrome://doubao-chat/` |

**msToken 细节（三次实测）**：

1. 自己随机编 160 字符 → `710022002`（服务端验 token，不是验格式）
2. 从客户端抓的 token 反复复用 → 多天有效、多次会话都过
3. token 不在 Cookie 里、不在页面 JS 存储里（`doubao://` 页 cookie/localStorage 为空）；
   只能从客户端请求 URL 里被动摘（CDP `Network.requestWillBeSent` 盯 `msToken=`）
4. 摘取工具：`tools/mstoken.mjs --harvest`（需要豆包客户端带 `--remote-debugging-port=9222` 启动）

## 二、图片输入（上传 + 登记 + 发送）

**上传**：客户端聊天页有一个 `input[type=file]`。CDP `DOM.setFileInputFiles` 塞本地文件后，
客户端自己完成 veImageX 上传（`/alice/resource/prepare_upload` 发 STS 凭证 → 签名 PUT → Commit）。
**无需自己实现火山 V4 签名**。上传结果从两个请求里都能回收：

- `/alice/message/pre_handle_v2_without_conv` 的 `uplink_entity.entity_content.image.key`（= `tos-cn-i-a9rns2rl98/<hex>.png`）
- `/top/v1?Action=CommitImageUpload` 的 SessionKey（base64 JSON，含 StoreUri）

**登记（关键，漏了就"装没看见图"）**：

```
POST /alice/message/pre_handle_v2_without_conv
{"uplink_entity":{"entity_type":2,"entity_content":{"image":{"key":"tos-cn-i-…/x.png"}},
 "identifier":"<uuid>"},"bot_id":"7338286299411103781","local_message_id":"<uuid>"}
→ {"code":0,"data":{"pre_generate_id":"61714106359981314"}}
```

不带 `local_message_id` → `400 binding: expr_path=local_message_id, cause=missing required parameter`。
`pre_generate_id` 不需要带进消息体；对齐靠 `identifier`。

**消息体**：`messages[0].content_block` = **先** `block_type:10052`（`attachment_block.attachments[]`：
`{type:1, identifier, image:{name, uri, image_ori:{url:"",width,height,format}, url_formats:{}}}`，
`upload_status:1, progress:100`），**后** `block_type:10000`（文本）。

**实测**：纯蓝 240×160 PNG → 「蓝色，横向长方形」；含登记的整链 7.8~16.6s。
未登记对照实验：模型回「我这边没有收到图片，请重新上传一下」。

**无签名直调 imagex**：`ApplyImageUpload` 裸调返回 `InvalidAuthorization`（100024）——
所以"借客户端"是当前最省的路子。若未来客户端去掉了 file input，才需要实现 STS 签名。

## 三、生图（2074 创作块）

- `STREAM_CHUNK` → `patch_op[].patch_value.content_block[]` 里 `block_type:2074` →
  `content.creation_block.creations[]` → `image.image_ori.url`（另有 `image_thumb`）
- **同一 creation 分两次下发**：第一次 `{image:{status,placeholder}}`（无 URL），第二次才带真 URL。
  去重键必须含 URL（`id|url`），否则占位块先注册 id、真图被当重复丢弃（1.5.x 实测踩坑）
- 直链是带签名的临时地址（`p3-flow-imagex-sign.byteimg.com`，`x-expires` 数天）
- 实测：12.1s / 17.6s 出图，PNG 5156KB / 6047KB（magic `89504e47` 校验通过）

## 四、生视频（两轮 + 异步消息）

1. 提需求 → 回「**视频生成参数确认**」（模型 Seedance 2.0 Mini / 时长 / 比例 / 创作方向），约 5s
2. 发「确认，开始生成」→ 回「大约需要 1-3 分钟…视频生成好后，我会主动发送给你」，约 7s
3. **mp4 不在这条 SSE 里**——是之后以普通消息到达。轮询 `POST /alice/conversation/latest_messagelist`
   （body `{request_list:[{conversation_id, bot_id}]}`）→ 最新消息里 `block_type:2074` →
   `creations[].video.download_url`（`v26-vdl.doubao.com/...`，带 `download=true`）
4. 实测两次：约 1.5~2.5 分钟出片；mp4 1.3MB / 1693KB（magic `ftyp`，duration 5.057s，384×216）
5. `/alice/message/list` 与 `/v2` 对我们的会话一律 `710010202 系统错误`（带不带 bot_id 都一样），
   **`latest_messagelist` 才是可用的那个**

## 五、文件产出（两种形状：10020 直链 / 10030 产物卡片）

**① `block_type 10020` = `file_block`（Word / PDF / 表格…）——带签名直链，可直接下载**：

```json
{"file_block":{"type":"docx","name":"项目周报.docx",
  "uri":"tos-cn-i-ik7evvg4ik/rc/pc/super_tool/7767d52….docx",
  "url":"https://p3-flow-sign.byteimg.com/tos-cn-i-ik7evvg4ik/…?x-expires=1795886814&x-signature=…",
  "size":"40267","path":"/home/user/Doubao/chats/<conv>/项目周报.docx"}}
```

实测（conv `38453706797311234`）：113s 生成 → `latest_messagelist` 回收 → 下载 HTTP 200、
`application/vnd.openxmlformats-officedocument.wordprocessingml.document`、39KB、magic `PK`。

**② `block_type 10030` = `artifact_block`（PPT 这类"超级工具"产物）——没有直链**：

- 只有 `resource_id + artifact_meta_id + artifact_version_id + conversation_id + title + status`
- 文件在豆包云盘（预览走 `internal-api-space.feishu.cn/space/api/file/f/cdp-slides-<rid>~noop`）
- 直连导出 `/samantha/otter/export/page/create`：`type` 必须 int（字符串 400 `expected int`）、
  `page_version:0` → `export page version invalid: 0`、`page_token` 用 resource_id/meta_id/version_id
  全部 `710022001 record not found` / `params invalid`——导出 token 只存在于云盘页面自己的会话。
  **结论：给「打开对话」链接当下载入口，直链导出未攻克**

**落库时机**：两类都可能**在 SSE 结束之后**才写进会话消息（Word 那次 SSE 里没有 10020）。
所以 `generate()` 拿不到媒体时会用 `collectMedia()` 轮询 `latest_messagelist` 再收一轮。

Word 会话里出现过的块类型（实测分布，供解析对齐）：
`10000` 文本 ×22、`10019` 文件操作（读技能/写文件）×14、`10020` **文件直链** ×3、
`10040` 思考状态 ×10、`10091` 耗时 ×2。PPT 会话则是 `10030` 产物卡片。
